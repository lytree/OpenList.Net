# OpenList.Net — Agent Instructions

## Build & Test

- **Build**: `dotnet build`
- **Run**: `dotnet run --project src/OpenList.Server` (listens `http://0.0.0.0:5244` by default)
- **Test**: `dotnet test` — uses **TUnit** (not NUnit), async convention: `await Assert.That(actual).Is(expected)`
- **Lint**: `dotnet format`
- **Cake build** (file-based `Cake.Sdk` script, `build/build.cs`): `dotnet run build/build.cs -- --target=<Task>` (e.g. `--target=CI`, `--target=Publish --semver=1.2.3`). `Cake.Sdk` is pinned via `global.json` → `msbuild-sdks`. See `build/build.cs` for all targets/args.
  - **Publish variants** via `--app=`: `server` (default — headless server; framework-dependent without `--rid`, self-contained with it) and `desktop` (`--app=desktop --rid=<rid>` — Avalonia GUI at bundle root + server under `server/` + `frontend/dist/`; always self-contained). Bundle names: `openlist-net[-desktop]-<rid>[-semver]`.
- **Dev server** (with frontend proxy): `dotnet run` in server + `pnpm dev` in `frontend/`
- **Vue frontend** (`frontend/`): `pnpm dev` (proxies `/api`, `/d`, `/p`, `/ad`, `/ap`, `/ae` to `DEV_PROXY_TARGET`, default `http://localhost:5244`). `pnpm typecheck | test | build` as usual. Note: vite's dep re-optimization can trip the sandbox's bulk-delete guard on `node_modules/.vite/deps_temp*`; if `pnpm dev` dies right after "optimized dependencies changed", remove that folder manually and restart.
- **Vue e2e acceptance** (Playwright, real backend): the whole A–H suite is orchestrated by `frontend/scripts/run-regression.sh` (15 rounds, one isolated DB/backend/fixture each; `bash frontend/scripts/run-regression.sh [round...]`). Fixtures are generated by `frontend/scripts/fixtures/gen_fixtures.py` (+ `setup.mjs` for mounts/libraries) — nothing is assumed to pre-exist on disk. Individual scripts: `verify-common.mjs` (auth/guards, all 11 admin pages, dark theme — A/E/G), `verify-preview.mjs` (archive tree/inner preview, `.url`, xlsx sheets, docx render, asciinema, 18), `verify-media.mjs` (browse grid / detail / embedded player / progress, 20; needs a scanned `E2E Movies` library — see §27), `verify-media-manage.mjs` (create library / scan running→completed via API polling / history / edit / delete, 20; self-mounts `/e2e`; note `storage/create`'s `addition` is a JSON **string**), `verify-media-dimensions.mjs` (persons/studios/series/taste/playlists/subtitles + per-person avatar & taxonomy deep-link titles, 48; self-mounts `.e2e/dim-fixture` and writes a 1×1 PNG for the `<thumb>` fixture — assert `naturalWidth > 0`, not just "an img exists"), `verify-messenger.mjs` (inbox: admin sends to a specific user, recipient badge/inbox/mark-read, cross-user write rejected with 404, 33; self-creates user `carol` and clears both inboxes), `verify-backup.mjs` (backup/restore: plaintext + encrypted export (the script really decrypts a field with `crypto-js`), wrong-password leaves the server untouched, delete→restore round-trip brings back a user (disabled) and a mount, second import is idempotent, self-lockout file is refused, 39; self-creates a probe user + mount), `verify-dashboard.mjs` (dashboard: 6 metric cards / per-library metadata health / driver+genre bars / system rows, all asserted against API-derived numbers, 40; owns `/e2e` mount from `FIXTURE=` and stages a user+share so counts aren't default values), `verify-scrape.mjs` (whole-library scrape button: status contract / button states / 400 passthrough / running-state UI via `page.route`, 39; self-creates `G:/Share/ol-v2-scrape` — real scraping can't run offline since the TMDB base URL is hard-coded, see §33), `verify-torrent.mjs` (bencode/SHA-1 torrent preview + `.torrent` drop, 15 — pass `EXPECT=` to the generated `expected.json`), `verify-preview-extra.mjs` (video360 via three.js + flash via Ruffle, 15; headless needs SwiftShader), `verify-editor.mjs` (CodeMirror editor, Ctrl+S writes to disk, non-UTF-8 read-only, 11), `verify-rename.mjs` (batch rename regex/sequence/find-replace, 12), `e2e-upload.mjs` (stream / form / chunked upload incl. skipped-chunk resume, 22 — set `BASE` to hit an already-running isolated backend instead of spawning one).

  For the file browser run `verify-v2.mjs` (tree/grid/pager/filter/README, 18) *before* `verify-ops.mjs` (new file / clean empty dirs / decompress / share / package download / recursive move / offline download, 24) — the latter rebuilds its fixture. Both expect an **isolated** backend (`AdminPassword=...`, temp SQLite, own port, `DistDir=frontend/dist`) with a `/e2e` mount; `MSYS_NO_PATHCONV=1` is required in Git Bash when passing `TARGET=/e2e` (the orchestrator already does this).
- **Desktop dev run**: `dotnet run --project src/OpenList.Desktop`. Desktop depends on the server at **build** time (a `ProjectReference` with `ReferenceOutputAssembly=false`), so building/running it auto-builds `OpenList.Server` first without pulling its dependencies into the desktop output. The target `ResolveOpenListServerCorePath` in `OpenList.Desktop.csproj` bakes the server's output assembly path into assembly metadata `OpenListServerPath`, which `OpenListCoreService.ResolveCorePath()` reads at runtime — so the core exe is located without guessing the TFM directory. Override via the `OPENLIST_SERVER_PATH` env var or the `CoreExePath` setting. In dev the core's working directory is likewise aligned to the server's build output (`bin/<Config>/<tfm>/`), so it reads that copy's `appsettings.json` and keeps its DB under `bin/<Config>/<tfm>/data/` — override with the `DataDir` setting.

## API Patterns

- **Minimal APIs only** — all endpoints in `src/OpenList.Server/Endpoints/` as static extension methods (`MapAuthApi`, `MapFsApi`, etc.), registered in `Program.cs`; the media domain is the exception — its endpoints live in `src/OpenList.Media/Endpoints/` and mount via `app.MapMediaModule()`
- **camelCase JSON** (`JsonNamingPolicy.CamelCase`)
- All responses wrapped in `Resp<T>`:
  ```json
  { "code": 200, "message": "success", "data": ... }
  ```
- Object mapping done manually (DTO ↔ entity). **Mapster is NOT actually used** — the package is referenced but `MappingConfig.Configure()` is never called / no `.Adapt<>` usage. Do not rely on it.
- Health check: `GET /ping` → `"pong"`

## Built-in Accounts (mirrors Go `internal/bootstrap/data/user.go`)

`DbInitializer.InitializeAsync` 按 Go 的 `initUser()`（= `initAdmin` + `initGuest`）建两个内置账号。
**两者判据相互独立**，这点很关键 —— 早期用「用户表为空」统一判据，结果游客先建好之后表永远不为空，
管理员再也建不出来。

| 账号 | 创建条件 | 角色 | 密码 | 权限 | 默认状态 | `IsBuiltIn` |
|---|---|---|---|---|---|---|
| `admin`（或配置的 `AdminUsername`） | **没有管理员** **且** 拿得到初始密码 | `Admin` | `AdminPassword` 配置值；devMode 下为 `admin` | `0x71FF` | 启用 | ✅ |
| `guest` | 没有 `guest` | `Guest` | `guest` | `0` | **禁用** | ✅ |

**拿不到密码就不建管理员**，改由 Web 安装向导 `POST /api/public/init/setup` 在用户首次访问时创建 ——
对齐 Go 的 `initAdmin`：它在既无 `--dev` 又无 `OPENLIST_ADMIN_PASSWORD` 时直接 `return`。
这样部署后不会留下人人可猜的 `admin/admin`。`AdminPassword` 默认为**空字符串**，`appsettings.json`
里也是 `""`；要自动建号就显式配置它（`appsettings.json` 或 `OpenList__AdminPassword` 环境变量）。
`devMode`（= `app.Environment.IsDevelopment()`，对应 Go 的 `--dev`）用 `admin` 作密码，免去本地每次都走向导。

其余要点：

- **`IsBuiltIn` 标记是保护的唯一依据**（列由 `AddUserIsBuiltIn` 迁移添加，并在其中回填旧库中最早的管理员）。`UserService.IsSuperAdmin` 读它，**不再**比较 `config.AdminUsername` —— 否则用户在管理界面改过用户名后保护就失效了。**按标记查账号时必须同时限定 `Role == Admin`**，否则会命中同样带标记的 guest（`ResetAdminPasswordAsync` 与 CLI 都踩过这个坑）。
- 内置 admin **不可删除 / 改名 / 降权 / 禁用 / 改权限位**，但**可以改密码**（那是被保留的唯一理由）。其余 admin 角色账号可正常删除。
- 安装向导走 `IUserService.CreateInitialAdminAsync`（**不是** `CreateAsync`）：它会打上 `IsBuiltIn`。该标记刻意没做进 `CreateUserReq`，否则已登录的管理员能凭空造出受保护账号；`CreateAsync` 恒定 `IsBuiltIn = false`。
- 已存在的管理员永不被配置覆盖 —— 凭据以数据库为准（管理界面 / 桌面端 / CLI 改的密码不会被下次启动打回）。
- 忘记密码的三条恢复路径：`POST /api/admin/user/reset_admin_password`、桌面端设置页、`cli/openlist admin random`（直连数据库，Web 层起不来时唯一可用的）。
- 注意：本项目多数"匿名访问"路径用的是代码内构造的虚拟 Guest（`Id=0`，见 `SignEndpoints` / `ShareDownloadEndpoints`），与库里这条 `guest` 记录无关。

## CLI (`src/OpenList.Cli`)

`openlist <command>`，System.CommandLine 解析；**不带子命令时转发启动 Web Server**（与 Go 裸跑一致）。

```
openlist admin info | set <password> | random
openlist storage list | disable <mount-path> | delete <id> [--force]
openlist cancel2fa <username>
```

它直连数据库（`DbInitializer` + `OpenListDbContext`），**不经过 DI 容器也不挂载存储驱动** ——
运维只想改密码，却因某个需要网络可达的驱动挂载失败而命令失败是不可接受的。同理不复用
`StorageService`（它依赖 `MountService`，构造即挂载全部驱动）。发布为 bundle 下的 `cli/`。

## Driver System

- **Auto-discovery**: `MountService` scans assemblies starting with `"OpenList"` for `DriverBase` subclasses. Adding a driver = create a class in `OpenList.Drivers` — no manual registration.
- **Own VFS (`OpenList.Vfs`)**: All drivers extend the in-house `FileSystem`, mounted via `MountFileSystem` (no third-party VFS dependency). Extension interfaces: `IFileSystemLinkProvider`, `IFileSystemUploader`, `IFileSystemWithDetails`, `IFileSystemArchiveReader`, `IFileSystemArchiveDecompress`, `IFileSystemDirectUploader`.
- **Driver config schema is backend-driven**: drivers declare `DriverItemAttributes` via `ConfigItems`; `StorageService.BuildDriverInfo` splits them into `common` (generated) + `additional` (from `ConfigItems`) and the frontend renders the form from `GET /admin/driver/list`. Field names double as translation keys in `frontend/src/lang/en/drivers.json` — a mismatch shows raw untranslated keys in the UI.
- **Runtime context injection**: `MountService.LoadAsync` calls `driver.AttachRuntime(mountPath, additionSink)` **before** `InitAsync`, giving the driver a `MountPath` and an `IStorageAdditionSink`.
- **Addition write-back** (`IStorageAdditionSink` / `StorageAdditionSink`): mirror of Go `op.MustSaveDriverStorage`. Drivers call `DriverBase.SaveAdditionAsync(addition)` to persist runtime config changes (chiefly refreshed OAuth tokens) back to `x_storages.Addition`. Serialization uses the object's **runtime type** so `[JsonPropertyName]` snake_case keys round-trip with `DriverConfig.GetAddition<T>()`. The sink is a singleton that opens its own DI scope per write (scoped `OpenListDbContext`); it short-circuits when the JSON is unchanged to avoid write amplification.
- **`LoadAsync` semantics**: a driver that returns successfully but leaves `System == null` is **not mounted** (config still saves). `LoadAllAsync` catches per-storage init failures and continues (mirrors Go `op.initStorage`); without this, one broken storage killed app startup.
- **Cloud driver base** (`OpenList.Drivers/Cloud/`, mirrors Go `drivers/aliyundrive_open/{limiter,util}.go`):
  - `CloudDriverBase` — sets `IsCloudDriver => true`, exposes a shared `HttpClient` (`CloudHttpClient.Shared`: auto-decompress, 30 s connect timeout, infinite overall timeout, 64 conns/host — a process-level singleton because drivers are created by `Activator.CreateInstance` with no DI), plus `ConfigureRateLimit(rps)` / `WaitRateLimitAsync`. Its `RefreshAndPersistTokensAsync` does refresh → apply → persist, in that order (so a DB write failure doesn't leave the live instance on a stale token).
  - `RequestRateLimiter` — token bucket with capacity 1, matching Go `rate.NewLimiter(rate.Limit(rps), 1)`. `limit_rate` is a **float in requests/second** (`<= 0` = unlimited). Concurrent waits are serialized so bursts can't exceed the limit.
  - `OAuthTokenRefresher` — retry loop mirroring Go's `refreshToken()` (1 initial + 3 retries = 4 default `MaxAttempts`), `ForJsonEndpoint(...)` helper for the common "POST JSON → `{access_token, refresh_token}`" shape. Treats **HTTP 200 with an empty `access_token` as a failure** (services do this when the refresh token is dead; writing that empty token would brick the storage), doesn't retry on caller cancellation, and includes the last error message in the thrown exception.
  - `OAuthTokens` — `access_token` / `refresh_token` pair.
  - `CallbackLimiterRegistry` / `CallbackLimiterRegistration` / `CallbackPermit` (`CallbackConcurrencyLimiter.cs`, mirrors Go `drivers/aliyundrive_open/callback.go`) — process-level proxy-callback admission registry **shared by Aliyun user id**; effective limit is the min of live registrations (`<=0` normalized to 1). Permits are held for the **whole response-body lifetime**, not just headers; acquire waits up to 1 s then throws `CallbackCapacityException` (Go `errs.TemporaryCapacity`, maps to S3 SlowDown later). Registry entries are reclaimed once a user has no registrations and no active permits. AliyundriveOpen wires it via `AttachCallbackLimiter(userId)` immediately after `getDriveInfo` returns the user id (the call sits right behind the limiter-slot switch in `InitAsync`) and unregisters on Dispose.
  - `CallbackRangeReader` (`CallbackRangeReader.cs`) — ranged reader over the Aliyun callback URL. Retries **only** verified capacity rejections (HTTP 403 + `RequestDeniedByCallback` + `ExceedMaxConcurrency`, see `IsCapacityRejection`), 3 attempts with exponential backoff + jitter, then `CallbackCapacityException`. Accepts 206 / full-range 200 / `Content-Range` start match; slices locally (`SkipLimitStream`) when the server ignores Range. Other errors fail immediately with the callback URL redacted from the message. Tests inject a fake `HttpMessageHandler`; `AcquireTimeout`/`RetryBaseDelay` are internal seams.

## Key Quirks

- **Auth**: JWT Bearer with configurable secret; auto-generated as 32 hex chars (2×Guid) if empty in config. Frontend sends token without `"Bearer "` prefix (custom `OnMessageReceived` handler).
- **Database**: defaults to `sqlite` (`data/data.db`); also supports `postgres`/`postgresql`. Table prefix: `x_`. Init: `MigrateAsync()` → falls back to `EnsureCreatedAsync()`. Add design-time migrations via `OpenListDbContextFactory` (uses SQLite).
- **CORS**: `AllowAnyOrigin/Method/Header` + expose `Content-Range`/`Content-Disposition` headers. Uses built-in `app.UseCors()` (NOT a custom middleware).
- **Rate limiters**: byte-level token bucket (mirrors Go `rate.Limiter` + `stream`). `RateLimiter` (per-limiter, `<=0` = unlimited, initial bucket full, token debt allowed), `RateLimitManager` (singleton holding client/server × download/upload limiters, refreshed from settings table), `RateLimitMiddleware` (wraps download/upload routes' response/request streams), `MaxAllowedMiddleware` (global concurrency gate when `MaxConnections > 0`). Middleware order: ErrorHandling → RequestLog → static → CORS → auth → MaxAllowed → RateLimit(download) → RateLimit(upload).
- **Request logging**: Serilog configured in `Program.cs` — console sink always on; file sink with `Log.MaxSize/MaxBackups/MaxAge` (Go lumberjack-style rotation) when `Log.Enable`. `RequestLogMiddleware` filters per `Log.Filter` (Enable + CIDR/path/method rules; path prefix when starts with `/`, else contains; all conditions ANDed).
- **Error handling**: `ErrorHandlingMiddleware` (outermost) converts unhandled exceptions to `Resp<T>` JSON — 500 "internal server error", `BadHttpRequestException` → 400. Mirrors Go `gin.Recovery`.
- **Config validation**: `AppConfiguration.Validate()` runs at startup and throws on invalid db type / HTTP·HTTPS port / MaxConnections / search_index backend / log params.
- **Swagger**: at `/swagger` + Scalar at `/scalar` (both Development only; Scalar points at `/swagger/v1/swagger.json`).
- **FTP/SFTP servers**: hosted services, disabled by default (`FTP.Enable`/`SFTP.Enable` in config).
- **Kestrel body limit**: 10 GB (for WebDAV uploads).
- **SPA fallback**: serves `index.html` from `DistDir` (`../../frontend/dist` by default).
- **Environment variables**: use `OpenList__` prefix (e.g. `OpenList__Database__Type=postgres`).

## BasePath 用户目录隔离落地（2026-10-17）

承接上节遗留的「BasePath 约束全项目普遍未落地」缺口，本次按 Go 语义把 `internal/model/user.go` 的 `User.JoinPath`（= `utils.JoinBasePath`）铺到 HTTP 层：

- **路径原语**（`OpenList.Vfs.UPath`）：新增 `FixAndCleanPath`（镜像 Go `utils.FixAndCleanPath`：转斜杠 + 补前导 `/` + 等价 `stdpath.Clean`）与 `TryJoinBasePath(basePath, reqPath, out result)`（镜像 Go `utils.JoinBasePath`）。**关键差异是相对路径守卫**：若 `reqPath` 原本含 `..`、清洗后已不含 `..`，说明那些 `..` 被规范化解析掉了、拼接会越出 `basePath`，因此返回 `false`（调用方回 403 `using relative path is not allowed`）。
- **用户级入口**（`OpenList.Core.Models.User.TryJoinPath`）：`BasePath` 为 null/空时等价 `/`（内置 admin / guest 情形，无约束）。
- **端点接线**（`OpenList.Server.Endpoints.FsEndpoints`）：新增 `JoinGuard(user, reqPath, out joined)`（返回非 null 即 403 结果）、`WriteGateAsync`（见下）与 `ParentPath`/`FindNearestMeta`/`CanWriteContent*`/`CanWrite`/`CanRead`/`MetaCoversPath`/`IsSubPath` 等 helper。读端点（`list`/`get`/`dirs`/`search`）、管理端点（`mkdir`/`rename`/`rename_batch`/`batch_rename`/`regex_rename`/`move`/`copy`/`remove`/`remove_empty_directory`）以及 `put`/`form`/`archive/*`/`scan`/`add_offline_download`/`other` 的路径参数**全部**先经 `JoinGuard` 套到用户 BasePath 之下。`/search` 的越界相对路径按 Go 回 **400**（其余回 403）。
- **写入门控**（`/fs/put`、`/fs/form`，镜像 Go `server/middlewares/fsup.go`）：先 `JoinGuard`，再 `WriteGateAsync` 三重校验 —— ① `user.CanWriteContent()`（权限位 3），除非 `CanWriteContentBypass`（meta `write` 且路径被 `PathEqual`/`IsSubPath` 且 `w_sub` 覆盖）；② `CanWrite(user, nearestMeta, parent)`（`meta.WriteUsers` 非空、不含 `user.Id` 且 meta 覆盖父路径 → 拒绝）。命中即 403。meta 解析失败不阻断写入（fail-open）。
- **管理端点权限门禁**（镜像 Go `fsmanage.go` / `fsbatch.go` 各端点内联检查）：`mkdir` 用 `CanWriteContent()`（权限位 3）；`rename`/`rename_batch`/`batch_rename`/`regex_rename` 用 `CanRename()`（位 4）；`move`/`recursive_move` 用 `CanMove()`（位 5）；`copy` 用 `CanCopy()`（位 6）；`remove`/`remove_empty_directory` 用 `CanRemove()`（位 7）。helper：`PermissionGuard(bool)`（权限位 → 403 `permission denied`）+ `MetaWriteGateAsync`（`common.CanWrite`）+ `ContentWriteGateAsync`（权限位 3 + bypass + `CanWrite` 组合，`WriteGateAsync` 委托之并作用于 `ParentPath(path)`）。校验顺序镜像 Go：`PermissionGuard` → `JoinGuard` → meta 门禁。**`admin` 不豁免**（`CanWrite`/`CanWriteContentBypass` 均不豁免，与 Go 一致）；内置 admin 权限位 `0x71FF` 全开，故不受影响。
- **刻意保留的 Go 例外**：`/fs/link` **不 join**（Go 注释：请求路径本就是完整路径）；`/fs/dirs` 的 `force_root` 分支**不 join** 且仅管理员可用（非管理员 403）。

**身份来源决策（「两者结合」）**：BasePath/Permission 随 JWT 一并签发（无状态快速路径），并在凭据变更时即时失效既有 token：

- `IAuthService.OpenListClaims` 新增 `BasePath`（`base_path`）/ `Permission`（`permission`）两个 claim 名；`JwtService.IssueToken` 把它们签进 token（`BasePath` 先经 `FixAndCleanPath` 规范化，null→`/`）；`UserService.UpdateAsync` 在 Role/Permission/BasePath 任一变化后登记失效。
- `UserTokenCutoffRegistry`（`OpenList.Infrastructure.Services`，**进程级 singleton**）：记「某用户在 T 之前签发的 token 全部失效」。截止点取整秒 **+1s**（JWT `nbf` 只有秒级精度；fail-closed —— 代价至多是变更瞬间登录的用户被要求重登，而不是旧权限 token 被放行）。`JwtBearerEvents.OnTokenValidated`（`Program.cs`）在标准校验通过后比对 `SecurityToken.ValidFrom`；`JwtService.ValidateTokenAsync`（S3 网关走这条入口）同样比对。**局限**：登记表在进程内存，重启清空、多实例各自独立（要强一致需分布式缓存）——与既有 `_revoked` 集合同性质。

**决策与已知缺口**：

- **admin 不豁免 BasePath**（严格对齐 Go；admin 通常 `BasePath="/"` → no-op）。旧 token 无 `base_path` claim 时 fail-open（等价 `/`）；失效登记表 fail-closed。
- ~~档 B 的权限位校验只覆盖 `/fs/put` + `/fs/form`；`mkdir`/`rename`/`remove` 等管理端点的权限位未校验~~ **已闭合**（2026-10-17 追加）：`mkdir`/`rename`/`rename_batch`/`batch_rename`/`regex_rename`/`move`/`copy`/`remove`/`remove_empty_directory`/`recursive_move` 均已补权限位 + `common.CanWrite` meta 白名单校验（见上「管理端点权限门禁」）。
- **直传门禁**（`/fs/get_direct_upload_info`，镜像 Go `server/handles/direct_upload.go`）：已补 `checkRelativePath(file_name)`（`UPath.IsValidName`，非纯名称 → 403）与目标**父目录**的 `CanWriteContent`（或 meta bypass）+ `CanWrite` 白名单门禁（复用 `ContentWriteGateAsync`，`parentPath = Dir(join(path, file_name))`，纯名称下恒等于 `path`）。**顺带修复**：`DirectUploadInfoReq` 原先缺 `[JsonPropertyName("file_name"/"file_size")]`，前端发送的 snake_case 从未绑定成功（`FileName` 恒为 null），已补属性。

- 既有缺陷（本次未改）：`Disabled` 未签进 token；`JwtService._revoked` 是实例字段（登出吊销不跨请求）；`FileSystemService.RemoveAsync` 仍忽略 `user`（路径约束现由端点层 `JoinGuard` 兜住）。

## S3 网关增强（2026-09-21，对照 Go v4.2.6）

`S3Endpoints` 在基础对象读写之上补齐了 S3 客户端实际依赖的能力：

- **分片上传（Multipart Upload）**（Go `server/s3/multipart.go` #2813）：`POST /s3/{bucket}/{key}?uploads` 初始化；`PUT …?partNumber=N&uploadId=X` 上传分片；`POST …?uploadId=X` 完成（body 为 `CompleteMultipartUpload` XML）；`DELETE …?uploadId=X` 中止；`GET /s3/{bucket}?uploads` 列出进行中上传。新增 `S3MultipartStore`（singleton，`src/OpenList.Server/Services/S3MultipartStore.cs`）：分片流式落盘到 `%TEMP%/openlist-s3-multipart/{uploadId}/part-NNNNN`，支持乱序上传，Complete 时按 partNumber 升序用 `ConcatStream` 合并后走 `PutStreamAsync` 写入目标；校验 parts 升序、逐分片 ETag 匹配、`Content-Length` 不符则报 `IncompleteBody`；失败保留会话以便重试，成功/中止后清理临时目录。**TTL 回收**（镜像 Go `startReaper`）：默认 24h 空闲即回收，间隔 = TTL/4 夹在 [10s, 1h]，可由 `S3.MultipartTTL`（Go duration 字符串，如 `24h`/`30m`）配置；`Program.cs` 启动时清扫上次运行遗留的孤儿目录并启动周期回收。ETag 规则：part = `"md5hex"`，complete = `"hex(md5(concat(part md5 原始字节)))-N"`。
- **ListObjectsV2**：`GET /s3/{bucket}?list-type=2` 返回 `KeyCount` / `ContinuationToken` / `NextContinuationToken` / `StartAfter`，对象先按 key 稳定排序再截断，支持 `continuation-token` / `start-after` 续传（V1 同步补 `marker` / `NextMarker` 与截断）。
- **服务端复制 CopyObject**：`PUT /s3/{bucket}/{key}` 带 `x-amz-copy-source: /srcBucket/srcKey` 头 → 复制到目标并返回 `CopyObjectResult`。
- **批量删除 DeleteObjects**：`POST /s3/{bucket}?delete`（XML `Delete/Object/Key` 列表）→ `DeleteResult`（逐条 `Deleted` 或 `Error`）。
- **Range 请求**：`GET /s3/{bucket}/{key}` 支持 `Range`，返回 **206 + `Content-Range`**（对应 Go `server/s3/range.go`）；`HEAD` 返回 `Accept-Ranges: bytes`。
- **实现注意**：解析请求体 XML 必须**异步**读取（`StreamReader.ReadToEndAsync` → `XmlDocument.LoadXml`）——ASP.NET Core 默认 `AllowSynchronousIO=false`，直接 `XmlDocument.Load(Request.Body)` 会抛 `InvalidOperationException` 并导致 Complete/DeleteObjects 静默失败（返回 400 / 空结果）。
